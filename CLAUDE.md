# CLAUDE.md

Unlease (stop leasing your data to Google, and unleash yourself): a self-hosted suite that replaces Google's apps, one app at a time, their data linked. Open source (MIT, github.com/stephenprn/unlease), meant to run on anyone's infrastructure. One server and one Docker image run the suite; the person installing it picks which apps it runs (setup, then Administration), and the apps share one setup, one look, the server's settings (Claude, S3, Seafile) and data that points from one into another. Four apps are ready: **Carnet** (id `notes`), a Google Keep replacement, **Pages** (id `pages`), a Notion-like knowledge base that shows Carnet's notes, collections and links and mentions contacts and events, **Contacts** (id `contacts`), a Google Contacts replacement, and **Agenda** (id `calendar`), a Google Calendar replacement that shows contacts' birthdays, Carnet's reminders and the days written in pages. French or English UI. One repository holds everything:

| Where | What | Stack |
| --- | --- | --- |
| `packages/core` | The platform every app shares: sync (records, clocks, merge, protocol), ids, references, rich text, i18n, formatting, search, the apps' registry | TypeScript, no dependency |
| `packages/design` | The design system's data: palette, appearance, shapes, pebbles, outlines, glyphs, emblems, the mark, Signika's widths | TypeScript, no dependency |
| `packages/notes` | Carnet's domain: its record types, models, services, its server routes' contracts, its English | TypeScript, no dependency |
| `packages/contacts` | Contacts' domain: the `contact` and `contactLabel` types, names, numbers (calls, comparison, WhatsApp), birthdays, addresses, search, vCard and Google CSV, the import's plan, its English | TypeScript, no dependency |
| `packages/calendar` | Agenda's domain: the `calendarEvent`, `calendarLabel` and `calendarFeed` types, days and wall times in a zone, repeat rules (RRULE) and occurrences, the views' layout, iCalendar, subscriptions and holidays, the edits of a repeating event, layers from the other apps, quick add, search, its English | TypeScript, no dependency |
| `packages/pages` | Pages' domain: the `block` type, blocks, page text and search, tables, embeds of Carnet's collections, questions about pages, copies, its English | TypeScript, no dependency |
| `web` | A web app per app, on the shell they share: `shared` (the shell, `@shared/*`), `notes` (Carnet's, `@notes/*`), `pages` (Pages', `@pages/*`), `contacts` (Contacts', `@contacts/*`), `calendar` (Agenda's, `@calendar/*`), `demo` (the demo and its fake server); one install, one lint, two builds | Vite, React, zustand, IndexedDB; served by the server (or any static host) |
| `mobile/shared` | What every Android app shares: storage, sync, setup, Administration, components, theme, native specs and Kotlin, fonts and textures (`@shared/*`; no install of its own) | React Native 0.88 bare CLI, op-sqlite, zustand, React Navigation, Reanimated |
| `mobile/notes`, `mobile/pages`, `mobile/contacts`, `mobile/calendar` | Carnet's, Pages', Contacts' and Agenda's Android apps, an APK each (`com.stephenprn.carnet`, `com.stephenprn.pages`, `com.stephenprn.contacts`, `com.stephenprn.agenda`) | the same, plus Notifee for Carnet, Contacts and Agenda |
| `server` | The suite's server: the platform (`src/`, with `src/claude` and `src/reading` shared by every app), and each app's module (`src/apps/notes`, `src/apps/pages`, `src/apps/contacts`, `src/apps/calendar`, listed in `src/apps/registry.ts`) | Node 24, Hono, node:sqlite, sharp, Anthropic SDK |
| `tools` | Generators (icons, fonts, textures, widgets, emoji) and the dictionaries' check | Node, Python |

Below, `core/x`, `design/x`, `notes/x`, `contacts/x`, `calendar/x` and `pages/x` are `packages/<name>/src/x`, imported as `@unlease/<name>/x` (a path alias in every program's tsconfig, bundler and test runner). The root is an npm workspace for `web` and `server` (one lockfile, installed at the root); each phone app is its own install (React Native pins its React, ESLint, Jest and Babel). One Docker image (root `Dockerfile`, `ghcr.io/stephenprn/unlease`) runs the server and serves the web apps on the same port (one image for every app: `docs/ARCHITECTURE.md#deployment` says why). `docs/ARCHITECTURE.md` explains the suite (what it shares and what each app owns, layout, adding an app, data across apps, the server's apps), the sync, Carnet's link reading and the deviations from the house structure; `docs/SELF-HOSTING.md` how others run it; `docs/RELEASING.md` how a release is cut.

## Open source and deployment

- **Nothing specific to one infrastructure goes in this repository**: no real hostnames, IPs, bucket names, tokens, device serials or personal paths, in code, docs, tests or examples (use `example.org`, `192.168.1.20`, placeholders). The maintainer's own deployment lives in a separate infrastructure repository (an Ansible role pulling the published image); anything about it belongs there, or in the git-ignored `CLAUDE.local.md`.
- **Configuration is the environment or the apps**: start-up settings are `UNLEASE_*` variables (`server/src/config.ts`, documented in `docs/SELF-HOSTING.md`, `server/README.md` and `.env.example`); everything else (which apps run, Claude, S3, Seafile, Seerr) is set in the setup and the apps' Administration. A new start-up setting goes in all four places; a new deployment shape (proxy, host) is a section of `docs/SELF-HOSTING.md`, never a code path for one host.
- **The image serves both**: `UNLEASE_WEB_DIR` points the server at the web builds (`web/dist`: `notes/`, `pages/`; `server/src/http/web.ts`: each app's files and page under its path, `/` to the first app the server runs, an address of v0.1's single app moved to its place with a 301, `_headers`'s security headers, hashed assets cached for good). A web app finds a server serving it (`servedByServer`) and fills in its address; hosted apart it needs `UNLEASE_CORS_ORIGINS`. Each app's service worker holds its own path only (`/notes`, `Service-Worker-Allowed`) and never touches `/api`; the root's `sw.js` retires v0.1's.
- **CI and releases** (`.github/workflows/`): `ci.yml` runs the packages' and each program's `verify` and the dictionary check on every push and pull request; `image.yml` publishes `:edge` (amd64 and arm64) from `main`. Keep them green. One version for the whole repository, set only by `npm run bump -- X.Y.Z` (`tools/release/version.mjs`: every `package.json` and lockfile, each phone app's `versionName` and the `versionCode` computed from it); a `vX.Y.Z` tag (`vX.Y.Z-rc.N` a candidate) runs `release.yml`: the tag checked against them and the changelog, `ci.yml`, the image (`:x.y.z`, `:x.y`, `:latest`) and an APK per phone app (`android.yml`'s matrix, all signed with the same upload key from repository secrets when they are set: the apps share their connection through a signature permission), then the GitHub release from `CHANGELOG.md` with a pinned `docker-compose.yml`, `example.env` and `SHA256SUMS`, then the web demo on GitHub Pages at https://demo.unlease.org (`pages.yml`, `npm run build:demo -w web`: the dev demo built as a static site for the site's path, the root there, `/<repository>/` on a fork's `github.io`; each app under its own, `/notes/`; the router keeps app paths and adds the suite's base only to the browser's address, `browserPath`/`appPath` in `web/shared/src/ui/router.tsx`, so an `href` to an app path goes through `browserPath`) (`docs/RELEASING.md`).
- **Docs are for strangers**: `README.md` (what it is, install from the latest release, upgrade), `docs/` (mapped in `docs/README.md`), `CONTRIBUTING.md`, `SECURITY.md`, `SUPPORT.md`. Anything a person running Unlease would notice adds its line to `CHANGELOG.md` under Unreleased (Added, Changed, Deprecated, Removed, Fixed, Security; a break starts with **Breaking:** and says what to do); a new variable, a migration order or a break also goes in the docs it touches.

## Commands

```bash
npm install                          # the root workspace: the packages' tools, web and server
npm run verify                       # shared packages: typecheck + lint + vitest
npm run verify -w web                # the web apps: typecheck + lint + vitest (a project per app) + both builds
npm run verify -w server             # server: typecheck + vitest
npm run dev -w web                   # both web apps on http://localhost:5173 (/notes, /pages); ?demo runs them on a fake server in the page (no key, nothing spent)
npm run dev -w server                # server from server/.env (UNLEASE_TOKEN, UNLEASE_DATA_DIR, UNLEASE_CORS_ORIGINS, UNLEASE_WEB_DIR)
(cd mobile/notes && npm install)     # Carnet for Android: its own install (mobile/pages the same for Pages)
(cd mobile/notes && LANG=fr_FR.UTF-8 npm run verify)  # typecheck + lint --quiet + jest, shared's tests too (its screen tests read French)
(cd mobile/notes && npm run android) # the dev build (com.stephenprn.carnet.dev) on a device/emulator (Metro: npm start); `./gradlew assembleDevRelease` a release-like one
node tools/i18n/check.mjs            # every translated sentence has its English where its code can count on it (--move [path]: files a sentence where all its users can count on it; --unwrapped <path>: French left outside t())
docker build -t unlease .           # the image: server + web apps
docker compose up -d                 # the published image, from docker-compose.yml and .env
```

Java 17 for Gradle (`JAVA_HOME` pointing at a JDK 17). Generators run from the repository root.

## The suite

- **Dependencies point down:** `core <- design <- notes, contacts <- calendar <- pages <- the programs`, enforced by the root ESLint for `packages/`: core and design know no app; an app's package sits after the apps whose data it shows (Agenda shows Contacts' birthdays and Carnet's reminders; Pages shows Carnet's and mentions Contacts' and Agenda's), and never imports one above it (Carnet never imports Pages, but for the types of `pages/sync/copies`; Carnet's and Contacts' packages never import each other nor Agenda's: Carnet's notes name the contacts and events they mention through `notes/services/noteMentions`, which the program feeds). The shared packages import no third-party module, platform or framework (no React, React Native, zustand, SQLite driver, Node or DOM API): they compile into Hermes, the browser and Node, and each program owns its dependencies.
- **Every app of the suite is in `core/apps.ts`** (`APPS`: id, name, slug, scheme, status, the apps it reads; `APP_WORDS` in `core/appWords.ts`), ready or announced, on or off, so a reference into an app this server does not run still reads as the suite's. The names are written out there only (`SUITE_NAME`; each app's `APP_NAME` in `<app>/brand` comes from `APPS`): the literals are a lint error elsewhere. "Carnet" is also an ordinary French word: where content means a notebook, not the app, disable the rule on that line with the reason.
- **An app is added in five places** (`docs/ARCHITECTURE.md#adding-an-app`): `core/apps.ts` (with `status: 'soon'` first), its package, its `ServerApp` in `server/src/apps/registry.ts`, its web app in `web/<app>` on `web/shared` (its entry, `installApp`, and its build in `web/scripts/build.mjs`, `web/build/brand.ts`, the server's `WEB_APPS`), its APK in `mobile/<app>` on `mobile/shared` (and the release's matrix, `tools/release/version.mjs`). The shell (`web/shared`, `mobile/shared`, the server's platform) never imports an app: an app brings its routes, screens, navigation, spotlight documents and Administration sections to it.
- **Apps on and off** (`ServerSettings.apps`, `core/sync/settings.ts`): the server runs the ready apps its setup or Administration turned on, never none. An app turned off keeps its records (synced, backed up); its routes answer 404, its work stops, its web app and its phone app show `appOffWords` (`AppOffScreen`). A client syncs only the types of its apps and those they read (`SyncRequest.types`, `typesOfApps(appsShownBy(app))`), keeps that list beside its cursor and pulls from 0 when it changes.
- **Record types are declared by their app** (`defineRecordTypes` in `core/sync/schema.ts`; Carnet's in `notes/sync/types.ts`, Pages' in `pages/sync/types.ts`): each field's check, the merged text fields with their limits and merge, the defaults a rollback writes back, the seeded ids. A type name belongs to one app for the whole suite (a second app declaring it throws). A program knows the types of the app packages it loads (`notes/sync/entities` loads Carnet's, `pages/sync/entities` Pages', `contacts/sync/entities` Contacts', `calendar/sync/entities` Agenda's; Carnet's phone app imports only types from `@unlease/pages`, so it never registers Pages' records); a record of a type no loaded app declares is refused whole.
- **Ids are UUIDv7** (`createId`, `core/services/ids.ts`, RFC 9562), minted on the device, unique across apps and sorted by creation. Only records every device seeds keep a fixed id (`inbox`, the starter collections' `line-*`), so two devices make the same one.
- **A reference is a type and an id** (`core/refs.ts`: `REF_TYPES`, each type's app and record type): a mention `{@type=id}` in rich text, a block's `targetType`/`targetId`, a field (a link's `copy`). A reference into an app the device does not have opens elsewhere (a phone app: the other app's scheme, `carnet://…`, `unlease-pages://…`, `unlease-contacts://…`, `unlease-agenda://…`, when installed, else its web app: `openInApp`; a web app: the other web app's page, `suitePlace`). Something new people can point at gets a type there (Contacts' `contact` and Agenda's `event` did). A type this build does not know (a newer client's) is kept as it is, never dropped or rewritten, and shows as unavailable (« Indisponible ici »): every switch on a target's type has a `default`.
- **An app's part of the server is a `ServerApp`** (`server/src/apps/types.ts`; Carnet's in `server/src/apps/notes/`, Pages' in `server/src/apps/pages/`): its routes, background work, hourly chores, the files its records use, their layout under its own folder in Seafile and archives, its Markdown in archives, its push rules. The platform (`server/src/` outside `apps/`: Claude's client and spending in `src/claude`, the guarded web reader in `src/reading`) never imports an app's package. A new app's module is listed in `server/src/apps/registry.ts`. Work across apps goes through the server: Carnet's « Garder une copie » asks Pages' module (`POST /api/pages/copies`), which writes the page and the link's `copy` under its clock.
- **Each package brings its English:** core's in `core/i18n/en/`, the design system's in `design/i18n/en.ts`, Carnet's in `notes/i18n/en/`, Contacts' in `contacts/i18n/en/`, Agenda's in `calendar/i18n/en/`, Pages' in `pages/i18n/en/`; each program adds those it shows at start (`addNotesEnglish()`, `addContactsEnglish()`, `addCalendarEnglish()`, which adds Carnet's and Contacts' too, `addPagesEnglish()`, which adds all of them). The shell's words (`web/shared`, `mobile/shared`) are core's (`core/i18n/en/shell.ts`): the shell counts on no app's dictionary. The check refuses a sentence whose English sits in a package its code cannot count on.

## Conventions that bite

- **Layers (phone):** `ui -> app -> data/platform -> packages`, enforced by each phone app's ESLint (`mobile/shared/config/eslint.cjs`), in `mobile/shared` too. `ui` never imports `@data`; `mobile/shared` imports no app; Pages' app may reach Carnet's public pieces (`@carnet/*`), never the other way. **Areas (web):** `web/shared` imports no app, `web/pages` may import `web/notes` (`@notes/*`), never the other way; only the demo and the tests' setup see them all (the web's ESLint).
- **Every user action is one `writeLocal` batch** (Carnet's phone actions `mobile/notes/src/app/store/actions.ts`; each client's library engine is shared, each app gives its projection: `mobile/shared/src/app/store/library.ts`, `web/shared/src/app/store/records.ts`): one HLC tick, persisted as pending, synced. Undo writes the old values with a newer clock. Never mutate records another way.
- **The server never writes under a device's clock:** a server-side write stamps through `ServerClock.stampOver` (after the clocks of the fields it overwrites, whatever the server's date). Pages' tree is repaired on the server (`server/src/apps/pages/tree.ts`: loops and orphans) and shown through `shownParent` on the clients; a repeating event's exception takes `exceptionId` (derived, so two devices write one record); a merged list field is declared `set: true` (Agenda's `exdates`); `placeAt` respaces a run of keys past `RESPACE_AT`.
- **Records are field-wise last-writer-wins** (`core/sync/record.ts`). Adding a synced field: add it to its type's declaration (`<app>/sync/types.ts`) and `<app>/sync/entities.ts`; never rename or remove one; ship the server before the apps (an older server drops the field for good).
- **Typed text merges instead** (a type's `merged` fields, `core/sync/textMerge.ts`; bases in `core/sync/bases.ts`): an editor saves what is typed through `saveTypedText(type, id, field, since, typed)` (not `updateNote`/`updateCheck`/`updateLink`), with `since` the text it last saved or showed. A new long free-text field goes in its type's `merged`, with its limit in `TEXT_LIMITS`.
- **A drawing is strokes as text** (`notes/services/drawing.ts`, a note of kind `drawing` in `note.drawing`, a page's `drawing` block in `block.drawing`): the field merges stroke by stroke (`mergeStrokes` through `mergeField`), so save it whole through `saveTypedText` (a note) or `saveBlockText(…, 'drawing')` (a block, kept in the page's undo), never another way. Coordinates are units of a sheet `DRAWING_WIDTH` wide; inks are keys (`ink` or a pigment), painted from the theme.
- **A text note's body is plain or formatted** (`note.rich`, `notes/services/noteBody.ts`: lines, `# `/`## `/`### ` headings, page rich-text marks): outside the editors read it through `bodyText(note)` (words) or `bodyMarkdown`, never `note.body`; the editors save through `saveNoteLines`. A plain note stays plain until its first mark.
- **Paper never moves the words:** the note editor's geometry is the same on every paper (a text note's title always keeps the ruled papers' skipped line; every body line, headings included, keeps the 26 pitch); ruled papers align on it, never the other way.
- **Positions from synced records go through `placeAt`** (or `positionBetween`/`positionsBetween` at an open end), never `keyBetween`: two devices can mint the same key, `keyBetween` throws between equal neighbours, and only `placeAt` fits an item between twins (it moves the later one; write its `moved` in the same batch).
- **A note's `color` is a pigment or a gradient** (`NoteColor`, `design/colors.ts`) and its paper is a separate `pattern`; collections and labels take pigments only (`asLineColor`). Both keys pass sync if well-formed: an unknown one draws plain. Paint a note with `noteBackdrop` (`design/backgrounds.ts`), the same CSS layers on both clients.
- **"Non classé" has the fixed id `inbox`** and is seeded with the genesis clock on every device. Never use its position as a neighbour for `placeAt` or `positionBetween`.
- **No underline or line-through on text cut by `numberOfLines` (phone):** React Native 0.88 draws decorations by hand and crashes when one falls past the last laid-out line (search "G" did). A card's search match is the peach background alone.
- **Dev builds are other apps** (phone): `debug` and `devRelease` are `com.stephenprn.<app>.dev` (« Carnet Dev », the icon striped, the debug key, `carnet-dev://`…: `mobile/shared/android/dev-builds.gradle`), beside the released apps and never reaching them (their own SuiteLink permission and siblings, their own schemes). So never write a package or a scheme of the suite out: `appPackage`/`appScheme` (`@shared/app/variant`) in JavaScript, `BuildConfig.APP_SCHEME` (`SCHEME_SUFFIX` for another app's) in Kotlin, `${suiteSuffix}`/`${appScheme}` in a manifest; a static resource that names them (`res/xml/shortcuts.xml`) is rewritten for the dev builds by that script (`mobile/README.md#dev-builds`).
- **The launcher's activity is an entry, not MainActivity** (phone): never rename or remove a `.Launcher<Palette>` entry (a phone that turned it on would lose the app from its launcher), and never name the launcher's activity (Notifee taps use `launchActivity()`, never `'default'`).
- **A multiline input that grows takes `useGrowingInput`** (phone; `TextField` does it): React Native's Android input scrolls a new line into view a frame before Fabric grows the field, and the words jump; the hook holds them (`TextFields` module). A `TextField` grows to eight lines (its own `maxHeight` if set) and is let go there, by its laid-out height (Fabric's content size never reaches the cap); React Native hands an input's ref over again at every keystroke, so the hook ignores a re-attach of the same input.
- **A field is frosted** (both clients): no grain lies behind the words typed. On the phone a field-like surface takes `frost` (`Organic`, `Tappable`: `OrganicView` paints the surface behind it, or the ground marked `GROUND_ID`, without its grain); on the web its rule takes `backdrop-filter: var(--field-frost)` beside `var(--field-veil)`.
- **A sheet's scrolling body is `SheetScroll` or `SheetFlatList`** (phone), never a plain `ScrollView`/`FlatList`: the sheet moves under the hand from anywhere, and only these hand the drag over at their top. A gesture-handler 3 pan reports no movement in `onStart`: decide a stroke's direction in `onUpdate`.
- **What scrolls dissolves where it slides under something on screen, never where it leaves the screen** (both clients; DESIGN.md's Scroll Edges): an eased 24 fade of the content itself, no blur, as strong as what lies beyond. On the phone `EdgeScrollView`, `EdgeFlatList`, `EdgeSectionList`, or `ScrollEdges` around an animated list (a sheet's `SheetScroll`/`SheetFlatList`, `RevealScrollView` and `SettingsScroll` already are), never a plain vertical `ScrollView`/`FlatList`: Android leaves an edge at the screen's own (the status bar, the gesture bar, the keyboard) plain by itself; a list right under a field takes `top={false}`, one in a card of its own both off; under a band that hides what scrolls beneath it (a pinned header), `insetTop`. On the web `useScrollEdges({ top, bottom })` names only the edges that lie under a bar, a head or a foot; a menu, a popover, a sheet's handle or a search field names none; a masked scroller that can hold a field paints its sheet (`data-scroll-sheet`), or the field's frost loses the grain. The caret's line never lies in a fade, and focus or the keyboard never jumps a long field to its top (the edge views handle both by themselves, both clients: never add a scroll-on-focus of your own). What scrolls with nothing under it runs down to the screen's edge, the room over the gesture bar inside its content, never as padding of the panel around it (a sheet's body takes it by itself, `useFootRoom`; the web's `.sheetBody` holds it).
- **An empty place says so** (both clients): `EmptyState` for a whole place (a collage scene), `EmptyLine` for a small one (a picker, a menu, a sheet's answers); never a blank list.
- **What Android hands an app arrives through its intake** (phone): a share, selected text (`PROCESS_TEXT`), another app's « add to calendar » or « add contact » (`ACTION_INSERT`), a `webcal:` or calendar-time link: each app's `IntakeModule` parks it and JavaScript takes it once setup is done, and nothing is saved until the person confirms (but a share to Carnet, which files at once). Static launcher shortcuts land on `ShortcutActivity` (never MainActivity: Android clears the task a static shortcut opens); Carnet's collections in the share sheet are plain dynamic sharing shortcuts (`ShortcutsModule`: a long-lived one may not carry a drawn icon). An `<activity-alias>` gets its shortcuts from the icon generator, never by hand.
- **A place is looked for over the whole screen** (phone): a `PlaceField` (or `searchPlace` from a row) opens `PlaceSearch`, which the screen shows through a `PlaceSearchHost` mounted at its root, after everything else.
- **Never import `Text`, `Touchable*` or `Switch` from react-native:** `AppText`, `Tappable` and `Switch` from `@shared/ui/components` (the web's switch, drawn the same: Android's own is off the system; a row that is the switch itself draws `SwitchMark`). `Tappable` draws its press tint inside the control's own corners (no `android_ripple`): give the control its shape in `style`. Set `fontFamily`, never `fontWeight` (each Signika weight is its own family; the night theme uses the `SignikaNight-*` grade).
- **A shaped surface on the phone is an `Organic`** (`@shared/ui/components`, Android's `OrganicView`), or a `Tappable`, which paints itself with one: every corner is the continuous corner (`squircleSegments` in `design/shapes.ts`, mirrored number for number in `mobile/shared/android/.../organic/Squircle.kt`: keep the two in step). A plain `View` with `corners()` draws plain circles. Its border is one colour (a side may go without). Corners come from `SHAPES` by role (the `RADII` scale), never a radius per item or by size; a shape nested in another is concentric (`concentric`). A `Tappable` cannot clip: what must stay inside its shape sits in an `Organic` with `overflow: 'hidden'`.
- **The brand's pebble is the one organic form** (`design/pebbles.ts`, the mark's stone): state and identity only (an icon button's tint, the capture button, the chosen place, a collection's emblem on its stone `EmblemStone`, pictures, swatches, the tick), never text. Phone: `pebble={turn}` on an `Organic`/`Tappable` (it gives under the press, natively). Web: `data-pebble={turn}` clips the element, `data-pebble-under={turn}` paints its `::before` (`--pebble-fill`) so its focus ring stays whole; a ring is a `PebbleEdge` (mark the owner `data-still`). A collection's stone turns `pebbleTurnOf(id)`.
- **A container takes its kind's outline** (`design/outline.ts`: the continuous corner at the kind's radius, the same for every item and every size, capped at `CORNER_CAP` of the shorter side so a one-line note stays a sheet): on the phone `outline="card"` on an `Organic`/`Tappable`; on the web `useOutline('card')` (clip + `OutlineEdge`, the lift on an unclipped parent as `--drop-*`, a focus ring outside), `OutlinedBox`, or `data-outline="kind"` (+ `data-edge`) for plain blocks. Web controls take `border-radius: var(--cut-<role>)`, scaled by `--corner-scale` where the browser draws `corner-shape: squircle`. A clipped web element loses its own box-shadow and focus outline: lift and ring it from outside.
- **Colours come from `design/palette.ts`** through the theme (`useThemedStyles`). Its contrast test is the authority. A screen lies on the ground (`GROUNDS`, two tones of the wall): `Ground` on the phone, `var(--ground-paint)` on the web (its film grain over the two tones, both fixed), never the flat wall alone.
- **The primary, the accent and the ground are the device's appearance** (`design/appearance.ts`; Réglages > Couleurs and Fond, the first run's « Apparence »): read them resolved for the theme (`theme.color`, `theme.ground` on the phone; the custom properties `applyAppearance` lays on `<html>` on the web), never `ROLES`/`GROUNDS` for those roles; a pinned bar paints the ground's slice (`GroundSlice`). A colour a person picks is fitted to keep every ratio (`fitGround`, `primaryRoles`, `accentRoles`); a new preset passes `__tests__/appearance`. The marks' pebble follows the primary too (`BrandMark`, `app`: Carnet's card and leaf, Pages' sheet, the Administration's server): draw it with `markColors(primary)`, never `MARK_COLORS` alone (the widgets and install icons are static and keep matcha; the web's tab draws the app's mark in the primary; each phone app's launcher icon is one of eight entries, one per palette, switched by `mobile/shared/src/app/launcherIcon.ts`). Pictures handed to another service (Seafile's logo, favicon and login background, `design/servicePictures.ts`) are drawn and encoded in the design package (`raster.ts`, `png.ts`, `jpeg.ts`, no library), so both apps make the same bytes; each app only saves them. The web's security policy refuses inline stylesheets: colours set at runtime go through the CSSOM. The sheets' grain is the `grain` setting, the ground's is the appearance's; both are the suite's, and so is the language: the web apps share one stored value (an open tab follows another's through the `storage` event); each phone app hands its siblings its choices and their times through SuiteLink (`grainAt`, `localeAt`), and follows a later one at start and whenever it comes to the front, never stamping what it took. The look (the theme, the colours and the ground, taken whole) is each app's: « Appliquer aux autres » (the slip after a change of look in Réglages, or the quiet button at the ground's foot) sends it to the apps ticked: on the phone a `lookOffer` naming them, which each takes when sent after its own `lookAt`; on the web written into their own `<device>.look.<app>` (the shared value keeps the first run's, for an app with none of its own yet).
- **Claude's key is a server setting set from the apps, one for every app** (`GET/PUT /api/settings`, `core/sync/settings.ts`; one client and one monthly budget, `server/src/claude`). Without it, links are kept plain (`status: 'skipped'`) and Pages asks nothing. Never put a key in source.
- **Claude writes in the link's language:** a link's `lang` is the interface language of the device that saved it (`getLocale()` in `addLinks`), set again when it is read again (`reanalyzeLink`, `readSkippedLinks`); the server names it on the message's first line (the system prompt stays fixed, so it stays cached) and reuses a cached reading only in the same language. Labels Claude writes come in both languages (`FACT_LABELS`, the prompt's lists); words the server matches against collection titles are French and English (`KIND_WORDS`).
- **Generated files:** `design/glyphs.ts` (`tools/icons/build_glyphs.mjs`, from Onde, Carnet's own icons drawn in `tools/icons/onde.mjs`: a new icon is drawn there, never imported), Android vector icons (`tools/icons/build_android_drawables.mjs`), the apps' launcher icons (`tools/icons/`), the widgets' `wgen_*` resources and `WidgetRes.kt` (`tools/widgets/build_widget_resources.mjs`), the paper grain `mobile/shared/assets/textures/grain.png` and `web/public/grain.png` and the ground's film grain `web/public/ground-grain.png` and `mobile/shared/assets/textures/ground-grain.png` (`tools/textures/build_grain.py`), the emoji pickers' catalogue `design/emojiCatalogue.json`, shared by both apps, its search in `design/emojiSearch.ts` (`tools/emoji/build_emoji.mjs`, from the web's `emojibase-data`), fonts (`tools/fonts/build_fonts.py`, into `mobile/shared/assets/fonts`, each with a slanted `_italic` twin React Native picks for italic; `npx react-native-asset` in each phone app links them), Signika's advance widths `design/advances.ts` (`tools/fonts/build_advances.py`). Collection emblems are data in `design/emblems.ts`, drafted by `tools/emblems/draft_emblems.py`; the marks' paths in `design/mark.ts`, by `tools/icons/draft_mark.mjs` (Carnet's), `draft_page_mark.mjs` (Pages'), `draft_drive_mark.mjs` (Seafile's).
- **Motion comes from `mobile/shared/src/ui/theme/motion.ts`** (web: `--ease-*`, `--duration-*`). An overlay plays its exit: keep its host mounted and render the animated child conditionally (Dialog, Menu, Snackbar), or drive it by hand (Sheet, Drawer); a subtree replaced whole skips its children's exits (`LayoutAnimationConfig skipExiting`, see `Wall`), or Reanimated misorders what draws over it.
- **Board cards are sized in the packages, never measured** (`layoutCard` in `notes/services/wall.ts`, Signika's widths): a card's paddings, rows and line counts must match it on both clients; change the anatomy there first.
- **A link's `filedBy` records who chose its collection** (`claude`, `person`, or null for "landed in Non classé"): an action that places a link on the person's say writes `person` (`moveLink`, `applyReview`, `trashLines` into another collection); "Ranger Non classé" (`inboxToSort`) skips those. Claude's later sorting goes through `POST /api/sort` and `applyMoves`, never the analyzer.
- **A link module** goes in `LINK_MODULES` with its name, description, fits, icon, needs and group (`notes/models/modules.ts`), its test in `moduleFits` (`notes/services/modules.ts`), and both clients' `ModuleBar` (its dialog or sheet); the "Modules" sheets list it on their own. One that asks the server gets a route in `server/src/apps/notes/routes.ts`, its stand-in in `web/demo/fakeServer.ts`, its own `ModuleTask` in `analyses`, and, when it searches the web, goes through `LinkSearches` (a variant of the same link, as a recap's episode, is kept under its own mark). Modules write nothing to the link on their own (an answer goes in its note only when the person adds it). Recipe scaling and step timers are core (`notes/services/recipes.ts`); the servings and timers are each app's memory (`kitchen.ts`).
- **A link is added through `addLinks`** (both apps' actions): it keeps an address once per collection and copies a reading from another collection (`notes/services/savedLinks.ts`); show its `addedMessage`. A new way to add links goes through it, never `writeLocal`.
- **Deleting collections that hold links asks where the links go** (`collectionsWithLinks`; phone `DeleteLineSheet`, web `askDeleteLines`): a new way to delete notes goes through it, never `trashNotes` alone. "Non classé" is never deleted nor asked about.
- **Each app is its own web app** (`web/<app>/src/main.tsx` installs its module, `web/shared/src/modules.ts`: what an app brings; Pages' installs Carnet's data beside it, `notesData`): its own page, build, manifest, icons, service worker, IndexedDB database and keys (its slug, `carnet`, `pages`), at its own path on one origin (`/notes/…`, `/pages/…`, the shell's places under it: `/notes/settings`, `/notes/admin`). No switch in the navigation: its brand is its mark and name, a link to its home (`AppBrand`); at the header's end (the drawer's top on a phone-sized window) the launcher (`AppLauncher`, as Google's): the apps the server runs, each its mark opening its own web app, the announced ones greyed. The Administration is the navigation's last row, under « Réglages » (its `server` glyph, `ADMIN_GLYPH`), never in the launcher. `navigate` to another app's path loads that app's page whole (`ownsPath`, `otherApp`); a reference into it is its address there (`suitePlace`). The device's settings (the server, the language, the grains, the first run's colours) are shared (`unlease.settings`, `getDeviceName`); each app's look is its own once chosen (`unlease.look.<app>`). Each app has its own bin, search and spotlight.
- **A notification that must ring on time is armed through its app's book** (Carnet's `useReminders.ts`, Contacts' `birthdayAlerts.ts`, Agenda's `reminders.ts`, on `planAlarms` in `mobile/shared/src/app/alarms.ts`): exact alarms (the apps that ring hold `USE_EXACT_ALARM`; never remove it from their manifests), an alarm kept in the book only once armed (Notifee throws on a moment already past), a late one rung at once while still worth it (`stillWorthRinging` for Agenda's, on the server too), a category on every notification. A new kind of notification goes the same way, and its app's `remindersTask` (index.js, run headless every hour and after the system's changes) reconciles it too. Docs: `docs/ARCHITECTURE.md#phone-specifics` (*Notifications on time*), the adb recipe in `mobile/README.md`.
- **Home-screen widgets draw what JavaScript hands them** (`mobile/notes/src/app/widgetPayloads.ts`, sent by `mobile/notes/src/app/widgets.ts`): what a widget shows changes there, never by reading SQLite in Kotlin; a write from a widget goes back through JavaScript (a tick: `setChecks`). Their resources come from `tools/widgets/build_widget_resources.mjs` (`wgen_*`, `WidgetRes.kt`); a widget layout takes no `View`/`Space` (a launcher refuses them) and no app font (titles: `WidgetType.kt`), and its root is `@android:id/background` with `clipToOutline="true"` and `outlineProvider="bounds"` (else the launcher clips it to its own corner radius, cutting ours). Their words are Android strings, English in `values/` and French in `values-fr/`; a launcher reads a layout's `@string` in the phone's language, so each layout's own words are written again from code in the app's language (`WidgetWords.kt`, layouts built through `widgetViews`): a new one goes in both.
- **The web demo answers the server's routes itself** (`web/demo/fakeServer.ts`, `?demo`): a new route needs its stand-in there.
- **URL lists are "collections" in the UI** ("lines" in the code: `Line*`, `useLines`, `createLine`); labels are "labels". A collection wears a cut-out emblem (`note.emblem`), "Non classé" the inbox tray (`'bac'`).
- **Inline atoms in rich text** (a mention `{@type=ID}`, a date `{@date=…}`) count one character in every offset: a new kind goes in `core/services/richText.ts` (parse, serialize, `richToPlain`, `sliceRich`), `richDisplay.ts` (the phone's fields), the web's `richDom.ts`, `pageText.ts` (Markdown) and every `run.kind` switch (TypeScript lists them).
- **Pages are `block` records (web and phone):** a page is a block and `parentId` its container (`pages/models/blocks.ts`). Change them through the page actions (`web/pages/src/app/store/pages.ts`, mirrored by Pages' phone app's `mobile/pages/src/app/store/pages.ts` and `pageHistory.ts`: one batch each, recorded in the page's undo history; change both together), never with `writeLocal` directly. Rich text is markup (`core/services/richText.ts`): edit it as runs (`parseRich`, `serializeRich`), never by slicing the string; a mention counts one character.
- **A new block kind** goes in `BLOCK_KINDS` and the schema, both clients' `BlockView`, the `/` menu (web `slashCommands.ts`, phone `PageSheets.tsx` `COMMANDS`), the clipboard (`clipboard.ts` `KEPT`, `pages/services/pageText.ts`), what Claude reads of a page (`blockWords` in `pages/services/pagesAsk.ts`), the backups' Markdown (`server/src/apps/pages/markdown.ts`), and if it holds a file the files in use and their layout (`server/src/apps/pages/files.ts`: the collector, the drive and the archives).
- **A contact is found by id through `resolveContact`** (`contacts/services/duplicates.ts`): a merged one is in the bin with `mergedInto`, and a mention or a link into it names and opens the one kept. Another app shows of Contacts what it mentions only (its `reads`, a namer for Carnet's `noteMentions`); where it is mentioned comes from each app's server module (`GET /api/<app>/mentions`, `core/sync/mentions.ts`), and a write into another app goes through its module (`POST /api/notes/gifts`).
- **Agenda's times are wall times in a zone** (`calendar/services/time.ts`): an event's `start`/`end` are `2026-11-02T14:30` in its `timeZone` (IANA), or days (`2026-11-02`, the end exclusive) for all day; count days and minutes with its helpers, never with `Date` in the device's zone, and reach an instant only through `wallToInstant`. A repeating event is changed through `calendar/services/editing.ts` (`saveOccurrence`, `moveOccurrence`, `deleteOccurrence`: this one, this one and the following, all), never by writing its fields by hand; the views take their occurrences from `occurrencesIn`.
- **Subscribed calendars and holidays are the server's records** (`calendarEvent` with a `feedId`): the apps never change them (« Dupliquer » makes one's own); the server writes them through `planFeed`, which rewrites only what changed.
- **Questions about pages are built on the device** (`askContext`, `pages/services/pagesAsk.ts`): never send a page whose `isPrivatePage` holds (its own `private` or a page above it), nor one in the bin; what goes to Claude is fixed English labels around the person's own words.
- **The setup is done once per server** (`core/services/setup.ts`, `ServerSettings.setup`): connect, then on a server not set up « Vos applications » and « Votre serveur », then « Vos données » (the app's import wizard, only while the app holds nothing: `setupImportShown`; « Plus tard » skips it), then the device's appearance; « Commencer » sends `setupDone`. Every device after it connects and picks its colours. Every field says where its value is found (`setupFieldHelp`, the forms' help); nothing is asked twice (the address when served, Claude's key once for every app, a phone's second app reusing the first one's connection and colours through `SuiteLink`, a signature-protected provider, a browser's second web app through the shared device settings). The app being set up stays on (« Cette application »), and shows only its own tasks.
- **Every import is the one wizard** (`core/services/importFlow.ts`; the pieces in `web/shared/src/ui/features/importing` and `mobile/shared/src/ui/features/importing`): source, a preview of every item with its fate (new, completed, already here, left out and why), choices, then one batch and its files, and a report. The app's package reads and plans; nothing is written before « Importer ». The web app hands it to the shell as `AppModule.importer` (Réglages › Données' first row, `/<app>/settings/import`, the first run's step), the phone app hosts it on its `Import` screen and passes it to its setup (`importer`). A new import source goes through the app's wizard, never a screen of its own.
- **« Effacer des données » is the shell's** (`core/services/erase.ts`, web `EraseScreen` from `AppModule.erase`, phone `EraseScreen` from each app's `Erase` route): the app's package says its parts and their tombstones (`<app>/services/erase.ts`, disjoint parts, dependants included, never a seeded record); the guards (the token checked by the server, « SUPPRIMER » typed, a backup first when S3 is set) stay in the shell. A new kind of record joins one of its app's parts.
- **Server settings live in the Administration**, in each app (web `/<app>/admin` and `/<app>/admin/<section>`, under « Réglages » at the navigation's foot; phone `Admin` with its `section`), not in Réglages (the device's own). Its home lists every section with its state in a line, the shared ones first (`SHARED_ADMIN_SECTIONS`, `core/services/admin.ts`: their ids are addresses), then the app's own (web `AppModule.adminSections`, phone `appSections`: an id, a title, a glyph, a one-line state, a body). A new one goes in `core/sync/settings.ts` (view and patch), `server/src/settings/store.ts` and `update.ts` (checked, and tried when it connects to something, before anything is stored), both Administration screens (a shared section, or an app's own with its line) and the web demo; the setup (`core/services/setup.ts`, the web's and `mobile/shared`'s `SetupScreen`) shows those same sections, as the rows of « Votre serveur » for the apps chosen (`setupTasks`). Secrets never leave the server: only their last four characters.
- **A blob's original may live in the drive** (Seafile): read blob bytes through `BlobStore.open` (`read()`), never from `blobs/` paths directly.
- **Every sentence the interface shows goes through `t()`** (`core/i18n`): the French is the key, its English goes in the area's part of its package's dictionary (Carnet's screens: `notes/i18n/en/`, Pages': `pages/i18n/en/`, the shell's: `core/i18n/en/shell.ts`; `node tools/i18n/check.mjs` lists what is missing; `--unwrapped <path>` finds French left outside). One sentence per key with `{slots}`, never fragments; `tc(context, …)` where one French needs two English (« Annuler »: `tc('undo', …)` on a slip); never `t` at module scope (a constant is `tx('…')`, translated where shown; a names map is `localized({…})`). Dates, numbers and `plural` follow the language already. A title shown goes through `shownTitle(note)` (the seeded « Non classé »). Nothing stored, synced or sent to Claude is translated.
- **A slip says its tone:** `showSnack(message, action, { tone })` with `info` (default), `success`, `warning` or `error` (web helpers `showError`, `showWarning`, `showUndo`).
