# CLAUDE.md

Unlease (stop leasing your data to Google, and unleash yourself) is a self-hosted suite that replaces Google's apps one at a time, their data linked. Open source (MIT, github.com/stephenprn/unlease), meant to run on anyone's infrastructure: one server and one Docker image run the suite, and the person installing it picks which apps it runs (setup, then Administration). The apps share one setup, one look, the server's settings (Claude, S3, Seafile) and data that points from one into another. French or English UI. Five apps are ready:

| App | id | Replaces | Shows of the others |
| --- | --- | --- | --- |
| **Carnet** | `notes` | Google Keep | mentions contacts and events |
| **Pages** | `pages` | Notion | Carnet's notes, collections and links; mentions contacts and events |
| **Contacts** | `contacts` | Google Contacts | |
| **Agenda** | `calendar` | Google Calendar | contacts' birthdays, Carnet's reminders, the days written in pages |
| **Clock** | `clock` | Google's Clock (alarms, timers, stopwatch, world clocks) | the weather and Agenda's day as it rings |

One repository holds everything:

| Where | What |
| --- | --- |
| `packages/core` | The platform every app shares: sync (records, clocks, merge, protocol), ids, references, rich text, i18n, formatting, search, the apps' registry |
| `packages/design` | The design system's data: palette, appearance, shapes, pebbles, outlines, glyphs, emblems, marks, Signika's widths |
| `packages/notes`, `contacts`, `calendar`, `pages`, `clock` | Each app's domain: its record types, models, services, its server routes' contracts, its French |
| `web` | A web app per app on the shell they share: `shared` (`@shared/*`), `notes`, `pages`, `contacts`, `calendar`, `clock` (`@<app>/*`), `demo` (the demo and its fake server). Vite, React, zustand, IndexedDB; one install, one lint, two builds |
| `mobile/shared` | What every Android app shares (`@shared/*`, no install of its own): storage, sync, setup, Administration, components, theme, native specs and Kotlin, fonts, textures. React Native 0.88 bare CLI, op-sqlite, zustand, React Navigation, Reanimated |
| `mobile/notes`, `pages`, `contacts`, `calendar`, `clock` | An APK each (`com.stephenprn.carnet`, `.pages`, `.contacts`, `.agenda`, `.clock`); Notifee in all but Pages; Clock's alarm engine in Kotlin |
| `server` | Node 24, Hono, node:sqlite, sharp, Anthropic SDK: the platform (`src/`, with `src/claude` and `src/reading` shared by every app) and each app's module (`src/apps/<app>`, listed in `src/apps/registry.ts`) |
| `tools` | Generators (icons, fonts, textures, widgets, emoji), the dictionaries' check, the release's version script |

Below, `core/x`, `design/x`, `notes/x`, `contacts/x`, `calendar/x`, `pages/x` and `clock/x` are `packages/<name>/src/x`, imported as `@unlease/<name>/x` (a path alias in every program's tsconfig, bundler and test runner). The root is an npm workspace for `web` and `server` (one lockfile, installed at the root); each phone app is its own install (React Native pins its React, ESLint, Jest and Babel).

Docs: `docs/ARCHITECTURE.md` (what the suite shares and what each app owns, adding an app, data across apps, the sync, Carnet's link reading, the phone's specifics), `docs/SELF-HOSTING.md`, `docs/RELEASING.md`, `mobile/README.md` (dev builds, adb recipes), `DESIGN.md` (the design system: read it before any interface work).

## Open source and deployment

- **Nothing specific to one infrastructure goes in this repository**: no real hostnames, IPs, bucket names, tokens, device serials or personal paths, in code, docs, tests or examples (use `example.org`, `192.168.1.20`, placeholders). The maintainer's own deployment lives in a separate infrastructure repository; anything about it belongs there, or in the git-ignored `CLAUDE.local.md`.
- **Configuration is the environment or the apps**: start-up settings are `UNLEASE_*` variables (`server/src/config.ts`, documented in `docs/SELF-HOSTING.md`, `server/README.md` and `.env.example`: a new one goes in all four); everything else (which apps run, Claude, S3, Seafile, Seerr) is set in the setup and the Administration. A new deployment shape (proxy, host) is a section of `docs/SELF-HOSTING.md`, never a code path for one host.
- **One image serves the server and the web apps** on the same port (`ghcr.io/stephenprn/unlease`; `UNLEASE_WEB_DIR` points at `web/dist`, `server/src/http/web.ts` serves each app under its path). A web app served by the server fills in its address (`servedByServer`); hosted apart it needs `UNLEASE_CORS_ORIGINS`. Each app's service worker holds its own path only and never touches `/api`.
- **CI and releases** (`.github/workflows/`, `docs/RELEASING.md`): `ci.yml` runs the packages' and each program's `verify` and the dictionary check on every push and pull request; `image.yml` publishes `:edge` from `main`. Keep them green. One version for the whole repository, set only by `npm run bump -- X.Y.Z`; a `vX.Y.Z` tag runs the release (image, an APK per app signed with the same upload key, the GitHub release from `CHANGELOG.md`, the web demo).
- **The web demo is built for a site's path** (`npm run build:demo -w web`, https://demo.unlease.org): the router keeps app paths and adds the suite's base only to the browser's address (`browserPath`/`appPath` in `web/shared/src/ui/router.tsx`), so an `href` to an app path goes through `browserPath`.
- **Docs are for strangers**: `README.md`, `docs/` (mapped in `docs/README.md`), `CONTRIBUTING.md`, `SECURITY.md`, `SUPPORT.md`. Anything a person running Unlease would notice adds its line to `CHANGELOG.md` under Unreleased (Added, Changed, Deprecated, Removed, Fixed, Security; a break starts with **Breaking:** and says what to do); a new variable, a migration order or a break also goes in the docs it touches.

## Commands

```bash
npm install                          # the root workspace: the packages' tools, web and server
npm run verify                       # shared packages: typecheck + lint + vitest
npm run verify -w web                # the web apps: typecheck + lint + vitest (a project per app) + both builds
npm run verify -w server             # server: typecheck + vitest
npm run dev -w web                   # the web apps on http://localhost:5173 (/notes, /pages, /contacts, /agenda, /clock); ?demo runs them on a fake server in the page (no key, nothing spent)
npm run dev -w server                # server from server/.env (UNLEASE_TOKEN, UNLEASE_DATA_DIR, UNLEASE_CORS_ORIGINS, UNLEASE_WEB_DIR)
(cd mobile/notes && npm install)     # a phone app: its own install (the same in mobile/pages, contacts, calendar, clock)
(cd mobile/notes && LANG=fr_FR.UTF-8 npm run verify)  # typecheck + lint --quiet + jest, shared's tests too (its screen tests read French)
(cd mobile/notes && npm run android) # the dev build (com.stephenprn.carnet.dev) on a device/emulator (Metro: npm start); `./gradlew assembleDevRelease` a release-like one
node tools/i18n/check.mjs            # every key is English and has its French where its code can count on it (--move [path]: files a sentence where all its users can count on it; --unwrapped <path>: French left in the code)
docker build -t unlease .            # the image: server + web apps
docker compose up -d                 # the published image, from docker-compose.yml and .env
```

Java 17 for Gradle (`JAVA_HOME` pointing at a JDK 17). Generators run from the repository root.

## The suite

- **Dependencies point down:** `core <- design <- notes, contacts <- calendar <- pages, clock <- the programs`, enforced by the root ESLint. Core and design know no app; an app's package sits after the apps whose data it shows and never imports one above it (Carnet imports only the types of `pages/sync/copies`; Carnet's and Contacts' packages never import each other nor Agenda's: a note names the contacts and events it mentions through `notes/services/noteMentions`, which the program feeds). The packages import no third-party module, platform or framework (no React, React Native, zustand, SQLite driver, Node or DOM API): they compile into Hermes, the browser and Node.
- **The shell never imports an app** (`web/shared`, `mobile/shared`, the server's platform outside `src/apps/`): an app brings its routes, screens, navigation, spotlight documents and Administration sections to it.
- **Every app of the suite is in `core/apps.ts`** (`APPS`: id, name, slug, scheme, status, the apps it reads; `APP_WORDS` in `core/appWords.ts`), ready or announced, on or off. The names are written out there only (`SUITE_NAME`; each app's `APP_NAME` in `<app>/brand`): the literals are a lint error elsewhere. "Carnet" is also an ordinary French word: where content means a notebook, disable the rule on that line with the reason.
- **An app is added in five places** (`docs/ARCHITECTURE.md#adding-an-app`): `core/apps.ts` (with `status: 'soon'` first), its package, its `ServerApp` in `server/src/apps/registry.ts`, its web app in `web/<app>` (its entry, `installApp`, its build in `web/scripts/build.mjs`, `web/build/brand.ts`, the server's `WEB_APPS`), its APK in `mobile/<app>` (and the release's matrix, `tools/release/version.mjs`).
- **Apps on and off** (`ServerSettings.apps`, `core/sync/settings.ts`): the server runs the ready apps its setup or Administration turned on, never none. An app turned off keeps its records (synced, backed up); its routes answer 404, its work stops, its clients show `appOffWords` (`AppOffScreen`). A client syncs only the types of its apps and those they read (`SyncRequest.types`, `typesOfApps(appsShownBy(app))`), keeps that list beside its cursor and pulls from 0 when it changes.
- **Record types are declared by their app** (`defineRecordTypes` in `core/sync/schema.ts`; each app's in `<app>/sync/types.ts`): each field's check, the merged text fields with their limits, the defaults a rollback writes back, the seeded ids. A type name belongs to one app (a second declaration throws). A program knows the types of the packages it loads (`<app>/sync/entities`; Carnet's phone app imports only types from `@unlease/pages`, so it never registers Pages' records); a record of a type no loaded app declares is refused whole.
- **Ids are UUIDv7** (`createId`, `core/services/ids.ts`), minted on the device. Only records every device seeds keep a fixed id (`inbox`, the starter collections' `line-*`), so two devices make the same one.
- **A reference is a type and an id** (`core/refs.ts`: `REF_TYPES`): a mention `{@type=id}` in rich text, a block's `targetType`/`targetId`, a field (a link's `copy`). Something new people can point at gets a type there. A reference into an app the device does not have opens elsewhere (phone: the other app's scheme when installed, else its web app, `openInApp`; web: `suitePlace`). A type this build does not know is kept as it is, never dropped or rewritten, and shows as unavailable: every switch on a target's type has a `default`.
- **An app's part of the server is a `ServerApp`** (`server/src/apps/types.ts`): its routes, background work, hourly chores, the files its records use, their layout in Seafile and archives, its Markdown in archives, its push rules. Work across apps goes through the server: Carnet's « Garder une copie » asks Pages' module (`POST /api/pages/copies`), which writes the page and the link's `copy` under its clock.
- **Each package brings its French** (`<package>/i18n/fr/`; the shell's words are core's, `core/i18n/fr/shell.ts`); each program adds those it shows at start (`addNotesFrench()`, `addContactsFrench()`, `addCalendarFrench()` which adds Carnet's and Contacts', `addPagesFrench()` which adds all, `addClockFrench()` which adds Agenda's).

## Conventions that bite

### Data and sync

- **Every user action is one `writeLocal` batch** (Carnet's phone actions in `mobile/notes/src/app/store/actions.ts`; the library engine is shared, each app gives its projection: `mobile/shared/src/app/store/library.ts`, `web/shared/src/app/store/records.ts`): one HLC tick, persisted as pending, synced. Undo writes the old values with a newer clock. Never mutate records another way.
- **Records are field-wise last-writer-wins** (`core/sync/record.ts`). Adding a synced field: add it to its type's declaration (`<app>/sync/types.ts`) and `<app>/sync/entities.ts`; never rename or remove one; ship the server before the apps (an older server drops the field for good).
- **Typed text merges instead** (a type's `merged` fields, `core/sync/textMerge.ts`): an editor saves what is typed through `saveTypedText(type, id, field, since, typed)` (not `updateNote`/`updateCheck`/`updateLink`), with `since` the text it last saved or showed. A new long free-text field goes in its type's `merged`, with its limit in `TEXT_LIMITS`.
- **The server never writes under a device's clock:** a server-side write stamps through `ServerClock.stampOver`. Pages' tree is repaired on the server (`server/src/apps/pages/tree.ts`) and shown through `shownParent` on the clients; a repeating event's exception takes `exceptionId` (derived, so two devices write one record); a merged list field is declared `set: true` (Agenda's `exdates`); `placeAt` respaces a run of keys past `RESPACE_AT`.
- **Positions from synced records go through `placeAt`** (or `positionBetween`/`positionsBetween` at an open end), never `keyBetween`: two devices can mint the same key, `keyBetween` throws between equal neighbours, and only `placeAt` fits an item between twins (it moves the later one; write its `moved` in the same batch).
- **"Non classé" has the fixed id `inbox`**, seeded with the genesis clock on every device. Never use its position as a neighbour for `placeAt` or `positionBetween`; it is never deleted.
- **A blob's original may live in the drive** (Seafile): read blob bytes through `BlobStore.open` (`read()`), never from `blobs/` paths.
- **Claude's key is a server setting, one for every app** (`GET/PUT /api/settings`; one client and one monthly budget, `server/src/claude`). Without it, links are kept plain (`status: 'skipped'`) and Pages asks nothing. Never put a key in source.

### Text and content

- **Every sentence the interface shows goes through `t()`** (`core/i18n`): English is the source and the key, its French goes in the area's part of its package's dictionary (the check refuses a French key, a missing one, and French in a package its code cannot count on). One sentence per key with `{slots}`, never fragments. Where one English needs two French, the key carries a context: `tc('notes', 'Labels')` or `'Labels [notes]'` in a constant (Carnet's « label » against the others' « libellé » is `[notes]`, a French plural `[many]`); `plural(n, 'selected', 'selected [many]')` names its plural when English cannot tell. Never `t` at module scope: a constant is `tx('…')`, translated where shown; a names map is `localized({…})`. A title shown goes through `shownTitle(note)` (`INBOX_TITLE` is data, stored in French; `INBOX_SHOWN_TITLE` is its key). Nothing stored, synced or sent to Claude is translated; the server's messages are English keys the apps translate.
- **Rich text is markup** (`core/services/richText.ts`): edit it as runs (`parseRich`, `serializeRich`), never by slicing the string. An inline atom (a mention `{@type=ID}`, a date `{@date=…}`) counts one character in every offset; a new kind goes in `richText.ts` (parse, serialize, `richToPlain`, `sliceRich`), `richDisplay.ts` (the phone's fields), the web's `richDom.ts`, `pageText.ts` (Markdown) and every `run.kind` switch.
- **A text note's body is plain or formatted** (`note.rich`, `notes/services/noteBody.ts`): outside the editors read it through `bodyText(note)` or `bodyMarkdown`, never `note.body`; the editors save through `saveNoteLines`. A plain note stays plain until its first mark.
- **A drawing is strokes as text** (`notes/services/drawing.ts`; `note.drawing`, a page's `block.drawing`): the field merges stroke by stroke, so save it whole through `saveTypedText` (a note) or `saveBlockText(…, 'drawing')` (a block, kept in the page's undo). Coordinates are units of a sheet `DRAWING_WIDTH` wide; inks are keys painted from the theme.

### Structure

- **Layers (phone):** `ui -> app -> data/platform -> packages`, enforced by each phone app's ESLint (`mobile/shared/config/eslint.cjs`). `ui` never imports `@data`; Pages' app may reach Carnet's public pieces (`@carnet/*`), never the other way.
- **Areas (web):** `web/pages` may import `web/notes` (`@notes/*`), never the other way; only the demo and the tests' setup see every app.
- **Each app is its own web app** (`web/<app>/src/main.tsx` installs its module, `web/shared/src/modules.ts`): its own page, build, manifest, icons, service worker, IndexedDB database and keys, at its own path on one origin (`/notes/…`, the shell's places under it: `/notes/settings`, `/notes/admin`), with its own bin, search and spotlight. No switch between apps in the navigation: the brand is the app's mark and name (`AppBrand`); the launcher at the header's end (`AppLauncher`) lists the apps the server runs, the announced ones greyed. The Administration is the navigation's last row under « Réglages » (`ADMIN_GLYPH`), never in the launcher, never an app of its own. `navigate` to another app's path loads that app's page whole (`ownsPath`, `otherApp`); a reference into it is its address there (`suitePlace`). The device's settings (the server, the language, the grains, the first run's colours) are shared by the web apps (`unlease.settings`).
- **The web demo answers the server's routes itself** (`web/demo/fakeServer.ts`, `?demo`): a new route needs its stand-in there.
- **Generated files, never edited by hand:** `design/glyphs.ts` (`tools/icons/build_glyphs.mjs`, from Onde in `tools/icons/onde.mjs`: a new icon is drawn there, never imported), Android vector icons and launcher icons (`tools/icons/`), the widgets' `wgen_*` resources and `WidgetRes.kt` (`tools/widgets/build_widget_resources.mjs`), the grains (`tools/textures/build_grain.py`), the emoji catalogue and its search (`tools/emoji/build_emoji.mjs`), fonts (`tools/fonts/build_fonts.py`; `npx react-native-asset` links them in each phone app), Signika's advance widths `design/advances.ts` (`tools/fonts/build_advances.py`). Emblems and marks are data (`design/emblems.ts`, `design/mark.ts`), drafted by `tools/emblems/` and `tools/icons/draft_*`.

### Design system (both clients; `DESIGN.md` has the detail)

- **Colours come from `design/palette.ts`** through the theme (`useThemedStyles`; `var(--…)` on the web); its contrast test is the authority. A screen lies on the ground: `Ground` on the phone, `var(--ground-paint)` on the web, never the flat wall alone.
- **The primary, the accent and the ground are the device's appearance** (`design/appearance.ts`): read them resolved for the theme (`theme.color`, `theme.ground`; the custom properties `applyAppearance` lays on `<html>`), never `ROLES`/`GROUNDS` for those roles; a pinned bar paints the ground's slice (`GroundSlice`). A colour a person picks is fitted to keep every ratio (`fitGround`, `primaryRoles`, `accentRoles`); a new preset passes `__tests__/appearance`. The marks' pebble follows the primary: draw it with `markColors(primary)`, never `MARK_COLORS` alone (the widgets and install icons are static and keep matcha; each phone app's launcher icon is one of eight entries, one per palette, switched by `mobile/shared/src/app/launcherIcon.ts`). The web's security policy refuses inline stylesheets: colours set at runtime go through the CSSOM.
- **What is the suite's and what is each app's:** the grains and the language are the suite's (web: one stored value, an open tab following another's through the `storage` event; phone: SuiteLink's `grainAt`/`localeAt`, a later choice followed at start and on coming to the front, never stamping what was taken). The look (theme, colours and ground, taken whole) is each app's; « Appliquer aux autres » sends it to the apps ticked (phone: a `lookOffer`, taken when sent after the app's own `lookAt`; web: written into their `unlease.look.<app>`).
- **Pictures handed to another service** (Seafile's logo, favicon and login background, `design/servicePictures.ts`) are drawn and encoded in the design package (`raster.ts`, `png.ts`, `jpeg.ts`, no library), so both clients make the same bytes.
- **A container takes its kind's outline** (`design/outline.ts`): phone `outline="card"` on an `Organic`/`Tappable`; web `useOutline('card')`, `OutlinedBox`, or `data-outline="kind"` (+ `data-edge`) for plain blocks. Web controls take `border-radius: var(--cut-<role>)`. A clipped web element loses its own box-shadow and focus outline: lift and ring it from outside. Corners come from `SHAPES` by role (the `RADII` scale), never a radius per item or by size; a shape nested in another is concentric (`concentric`).
- **The pebble is the one organic form** (`design/pebbles.ts`): state and identity only (an icon button's tint, the capture button, the chosen place, a collection's emblem on its stone, pictures, swatches, the tick), never text. Phone: `pebble={turn}` on an `Organic`/`Tappable`. Web: `data-pebble={turn}` clips the element, `data-pebble-under={turn}` paints its `::before` so its focus ring stays whole; a ring is a `PebbleEdge`. A collection's stone turns `pebbleTurnOf(id)`.
- **A checkbox is `Checkbox` or `CheckMark`** (`design/checkbox.ts`; `CheckMark` for a row that is the checkbox itself), never the `box`/`boxChecked` glyph, which only names a to-do in a menu. Checked is ink for a choice, the second ink for an item done (`recede`); never matcha.
- **A field is frosted:** no grain lies behind the words typed. Phone: a field-like surface takes `frost` (`Organic`, `Tappable`); web: `backdrop-filter: var(--field-frost)` beside `var(--field-veil)`.
- **A bar meets what scrolls with a hard line; a fade only says content continues.** A header, a top bar, a sheet's or dialog's head, a sticky head paints the ground and draws one hairline once content has gone under it, none at rest; a footer's line stays drawn on the phone (`footEdge`, `FormFoot`) and shows on the web while content runs under it. Never a fade, a shadow or a blur under a bar. The 24 fade is kept for what scrolls sideways and for a vertical scroller capped inside a card, panel, menu or popover, only while it overflows. Phone: the edge scrollers (`EdgeScrollView`, `EdgeFlatList`, `EdgeSectionList`, `ScrollEdges`, `SheetScroll`/`SheetFlatList`, `RevealScrollView`, `SettingsScroll`), never a plain vertical `ScrollView`/`FlatList`. Web: `useScrollEdges`, `usePageEdges`; the fade is an explicit opt-in. The edge views keep the caret clear of bars and stop focus jumps by themselves: never add a scroll-on-focus of your own. What scrolls with nothing under it runs to the screen's edge, the gesture bar's room inside its content (`useFootRoom`; the web's `.sheetBody`), never as padding of the panel around it.
- **An empty place says so:** `EmptyState` for a whole place, `EmptyLine` for a small one (a picker, a menu, a sheet's answers); never a blank list.
- **Motion comes from `mobile/shared/src/ui/theme/motion.ts`** (web: `--ease-*`, `--duration-*`). An overlay plays its exit: keep its host mounted and render the animated child conditionally (Dialog, Menu, Snackbar), or drive it by hand (Sheet, Drawer); a subtree replaced whole skips its children's exits (`LayoutAnimationConfig skipExiting`, see `Wall`).
- **A slip says its tone:** `showSnack(message, action, { tone })` with `info` (default), `success`, `warning` or `error` (web helpers `showError`, `showWarning`, `showUndo`).

### Phone (React Native, Android)

- **Never import `Text`, `Touchable*` or `Switch` from react-native:** `AppText`, `Tappable` and `Switch` from `@shared/ui/components` (a row that is the switch itself draws `SwitchMark`). `Tappable` draws its press tint inside the control's own corners (no `android_ripple`): give the control its shape in `style`. Set `fontFamily`, never `fontWeight` (each Signika weight is its own family; the night theme uses the `SignikaNight-*` grade).
- **A shaped surface is an `Organic`** (Android's `OrganicView`), or a `Tappable`, which paints itself with one: a plain `View` with `corners()` draws plain circles. Its border is one colour. A `Tappable` cannot clip: what must stay inside its shape sits in an `Organic` with `overflow: 'hidden'`. The corner's numbers are mirrored in `mobile/shared/android/.../organic/Squircle.kt` (`squircleSegments` in `design/shapes.ts`): keep the two in step.
- **No underline or line-through on text cut by `numberOfLines`:** React Native 0.88 crashes when a decoration falls past the last laid-out line. A card's search match is the peach background alone.
- **A multiline input that grows takes `useGrowingInput`** (`TextField` does it), or the words jump as a line is added.
- **A sheet's scrolling body is `SheetScroll` or `SheetFlatList`**, never a plain `ScrollView`/`FlatList`: only these hand the drag over to the sheet at their top. A gesture-handler 3 pan reports no movement in `onStart`: decide a stroke's direction in `onUpdate`.
- **A place is looked for over the whole screen:** a `PlaceField` (or `searchPlace` from a row) opens `PlaceSearch`, shown by a `PlaceSearchHost` mounted at the screen's root, after everything else.
- **Dev builds are other apps:** `debug` and `devRelease` are `com.stephenprn.<app>.dev` (« Carnet Dev », the debug key, their own schemes and SuiteLink permission: `mobile/shared/android/dev-builds.gradle`, `mobile/README.md#dev-builds`). So never write a package or a scheme of the suite out: `appPackage`/`appScheme` (`@shared/app/variant`) in JavaScript, `BuildConfig.APP_SCHEME` (`SCHEME_SUFFIX` for another app's) in Kotlin, `${suiteSuffix}`/`${appScheme}` in a manifest.
- **The launcher's activity is an entry, not MainActivity:** never rename or remove a `.Launcher<Palette>` entry (a phone that turned it on would lose the app from its launcher), and never name the launcher's activity (Notifee taps use `launchActivity()`, never `'default'`). An `<activity-alias>` gets its shortcuts from the icon generator, never by hand.
- **What Android hands an app arrives through its intake:** a share, selected text (`PROCESS_TEXT`), « add to calendar » or « add contact » (`ACTION_INSERT`), a `webcal:` or calendar-time link: each app's `IntakeModule` parks it, JavaScript takes it once setup is done, and nothing is saved until the person confirms (but a share to Carnet, which files at once). Static launcher shortcuts land on `ShortcutActivity`, never MainActivity (Android clears the task a static shortcut opens); Carnet's collections in the share sheet are plain dynamic sharing shortcuts (`ShortcutsModule`: a long-lived one may not carry a drawn icon).
- **A notification that must ring on time is armed through its app's book** (Carnet's `useReminders.ts`, Contacts' `birthdayAlerts.ts`, Agenda's `reminders.ts`, on `planAlarms` in `mobile/shared/src/app/alarms.ts`): exact alarms (never remove `USE_EXACT_ALARM` from a manifest that rings), an alarm kept in the book only once armed (Notifee throws on a moment already past), a late one rung at once while still worth it, a category on every notification. A new kind goes the same way, and its app's `remindersTask` (index.js, run headless every hour) reconciles it too (`docs/ARCHITECTURE.md#phone-specifics`; the adb recipe in `mobile/README.md`).
- **Home-screen widgets draw what JavaScript hands them** (`mobile/<app>/src/app/widgetPayloads.ts`): what a widget shows changes there, never by reading SQLite in Kotlin; a write from a widget goes back through JavaScript. A widget layout takes no `View`/`Space` and no app font (titles: `WidgetType.kt`), and its root is `@android:id/background` with `clipToOutline="true"` and `outlineProvider="bounds"`. Its words are Android strings (`values/`, `values-fr/`), written again from code in the app's language (`WidgetWords.kt`, layouts built through `widgetViews`): a new one goes in both. A widget that fills a list has its own preview layout (`widget_*_preview.xml`, sample content): a launcher fills no list in its picker.
- **The phone's own address book and calendar are written one way, under the app's own account** (`@shared/app/phoneMirror`, each app's `mirror/PhoneMirrorModule.kt`): every query and write names the account's type (`@string/unlease_account_type`), never the phone's other contacts or events; what a record becomes there is its package's planner (`<app>/services/phoneMirror.ts`).

### The shell (setup, import, erase, Administration)

- **The setup is done once per server** (`core/services/setup.ts`, `ServerSettings.setup`; both clients' `SetupScreen`): connect, then on a server not set up « Vos applications » and « Votre serveur », then « Vos données » (the app's import wizard, only while the app holds nothing), then the device's appearance; « Commencer » sends `setupDone`, and every device after it only connects and picks its colours. Every field says where its value is found (`setupFieldHelp`); nothing is asked twice (a phone's second app takes the first one's connection and look through `SuiteLink`, a browser's second web app the shared device settings).
- **Every import is the one wizard** (`core/services/importFlow.ts`; the pieces in each shell's `ui/features/importing`): source, a preview of every item with its fate, choices, then one batch and a report. The app's package reads and plans; nothing is written before « Importer ». The web app hands it to the shell as `AppModule.importer`, the phone app hosts it on its `Import` screen and passes it to its setup. A new import source goes through the app's wizard, never a screen of its own.
- **« Effacer des données » is the shell's** (`core/services/erase.ts`): the app's package says its parts and their tombstones (`<app>/services/erase.ts`: disjoint parts, dependants included, never a seeded record); the guards stay in the shell. A new kind of record joins one of its app's parts.
- **Server settings live in the Administration**, in each app, not in Réglages (the device's own). The shared sections come first (`SHARED_ADMIN_SECTIONS`, `core/services/admin.ts`: their ids are addresses), then the app's own (web `AppModule.adminSections`, phone `appSections`). A new setting goes in `core/sync/settings.ts` (view and patch), `server/src/settings/store.ts` and `update.ts` (checked, and tried when it connects to something, before anything is stored), both Administration screens, the setup's « Votre serveur » rows (`setupTasks`) and the web demo. Secrets never leave the server: only their last four characters.
- **What leans on a server feature shows only once the server says it is set up** (`useServerFeature`): Claude's modules, « Demander à Claude », sorting by Claude.

### Carnet

- **URL lists are "collections" in the UI**, "lines" in the code (`Line*`, `useLines`, `createLine`); labels are "labels". A note's `color` is a pigment or a gradient (`NoteColor`, `design/colors.ts`) and its paper a separate `pattern`; collections and labels take pigments only (`asLineColor`); an unknown key draws plain. Paint a note with `noteBackdrop` (`design/backgrounds.ts`).
- **Board cards are sized in the packages, never measured** (`layoutCard` in `notes/services/wall.ts`): a card's paddings, rows and line counts must match it on both clients; change the anatomy there first.
- **Paper never moves the words:** the note editor's geometry is the same on every paper (a text note's title keeps the ruled papers' skipped line; every body line, headings included, keeps the 26 pitch); ruled papers align on it, never the other way.
- **A link is added through `addLinks`** (both clients' actions): it keeps an address once per collection and copies a reading from another collection (`notes/services/savedLinks.ts`); show its `addedMessage`. A new way to add links goes through it, never `writeLocal`.
- **A link's `filedBy` records who chose its collection** (`claude`, `person`, or null for "landed in Non classé"): an action that places a link on the person's say writes `person` (`moveLink`, `applyReview`, `trashLines` into another collection); "Ranger Non classé" (`inboxToSort`) skips those. Claude's later sorting goes through `POST /api/sort` and `applyMoves`, never the analyzer.
- **Deleting collections that hold links asks where the links go** (`collectionsWithLinks`; phone `DeleteLineSheet`, web `askDeleteLines`): a new way to delete notes goes through it, never `trashNotes` alone.
- **Claude writes in the link's language:** a link's `lang` is the interface language of the device that saved it (`getLocale()` in `addLinks`), set again when it is read again; the server names it on the message's first line (the system prompt stays fixed, so it stays cached). Labels Claude writes come in both languages (`FACT_LABELS`); words the server matches against collection titles are French and English (`KIND_WORDS`).
- **A link module** goes in `LINK_MODULES` (`notes/models/modules.ts`), its test in `moduleFits` (`notes/services/modules.ts`), and both clients' `ModuleBar`. One that asks the server gets a route in `server/src/apps/notes/routes.ts`, its stand-in in `web/demo/fakeServer.ts`, its own `ModuleTask` in `analyses`, and, when it searches the web, goes through `LinkSearches`. A module writes nothing to the link on its own.

### Pages

- **Pages are `block` records:** a page is a block and `parentId` its container (`pages/models/blocks.ts`). Change them through the page actions (`web/pages/src/app/store/pages.ts`, mirrored by `mobile/pages/src/app/store/pages.ts` and `pageHistory.ts`: one batch each, recorded in the page's undo; change both together), never with `writeLocal` directly.
- **A new block kind** goes in `BLOCK_KINDS` and the schema, both clients' `BlockView`, the `/` menu (web `slashCommands.ts`, phone `PageSheets.tsx` `COMMANDS`), the clipboard (`clipboard.ts` `KEPT`, `pages/services/pageText.ts`), what Claude reads of a page (`blockWords` in `pages/services/pagesAsk.ts`), the backups' Markdown (`server/src/apps/pages/markdown.ts`), and if it holds a file `server/src/apps/pages/files.ts`.
- **Questions about pages are built on the device** (`askContext`, `pages/services/pagesAsk.ts`): never send a page whose `isPrivatePage` holds (its own `private` or a page above it), nor one in the bin; what goes to Claude is fixed English labels around the person's own words.

### Contacts

- **A contact is found by id through `resolveContact`** (`contacts/services/duplicates.ts`): a merged one is in the bin with `mergedInto`, and a mention or a link into it names and opens the one kept. Another app shows of Contacts only what it mentions; where a contact is mentioned comes from each app's server module (`GET /api/<app>/mentions`), and a write into another app goes through its module (`POST /api/notes/gifts`).

### Agenda

- **Times are wall times in a zone** (`calendar/services/time.ts`): an event's `start`/`end` are `2026-11-02T14:30` in its `timeZone` (IANA), or days (`2026-11-02`, the end exclusive) for all day. Count days and minutes with its helpers, never with `Date` in the device's zone; reach an instant only through `wallToInstant`.
- **A repeating event is changed through `calendar/services/editing.ts`** (`saveOccurrence`, `moveOccurrence`, `deleteOccurrence`: this one, this and the following, all), never by writing its fields by hand; the views take their occurrences from `occurrencesIn`.
- **Subscribed calendars and holidays are the server's records** (`calendarEvent` with a `feedId`): the apps never change them (« Dupliquer » makes one's own); the server writes them through `planFeed`.

### Clock

- **Alarms ring through the engine, never through Notifee** (`mobile/clock/android/.../alarm`, spec `NativeAlarmEngine.ts`): JavaScript only hands it the plan (`clock/services/engine.ts` through `app/engine.ts`, whenever an alarm or a ringing setting changes); the engine counts each next ring (`Civil.kt`, `AlarmPlan.kt`, mirroring `clock/services/schedule.ts` number for number: change both, and both tests, together), arms it with `setAlarmClock` and answers snooze and stop without JavaScript. Nothing is written to a record when an alarm rings. Notifee carries only Clock's notices (the evening check, the notice before an alarm).
- **Timers and the stopwatch run in the engine too** (`mobile/clock/android/.../tools`, the same spec): JavaScript asks (`app/store/toolsStore.ts`) and follows `onTools`, never counts or arms anything itself; a running timer and the stopwatch are the device's, never records (only saved timers and world clocks are: `timer`, `worldClock`). A widget's button acts through `ToolReceiver` with the app closed. Their notifications, widgets and window count by themselves (Chronometer, TextClock): never redraw each second.
