# CLAUDE.md

Unlease (stop leasing your data to Google, and unleash yourself): a self-hosted suite that replaces Google's apps, one app at a time, their data linked. Open source (MIT, github.com/stephenprn/unlease), meant to run on anyone's infrastructure. One server runs the suite; each app has its own clients and its own part of the server, and installs on its own. The first app is **Carnet** (id `notes`): a Google Keep replacement (French or English UI) with a Notion-like side (pages) on the web and the phone. One repository holds everything:

| Where | What | Stack |
| --- | --- | --- |
| `packages/core` | The platform every app shares: sync (records, clocks, merge, protocol), ids, references, rich text, i18n, formatting, search, the apps' registry | TypeScript, no dependency |
| `packages/design` | The design system's data: palette, appearance, shapes, pebbles, outlines, glyphs, emblems, the mark, Signika's widths | TypeScript, no dependency |
| `packages/notes` | Carnet's domain: its record types, models, services, its server routes' contracts, its English | TypeScript, no dependency |
| `mobile/notes` | Carnet for Android | React Native 0.88 bare CLI, op-sqlite, zustand, React Navigation, Reanimated, Notifee |
| `web/notes` | Carnet on the web | Vite, React, zustand, IndexedDB; served by the server (or any static host) |
| `server` | The suite's server: the platform, and each app's module (`src/apps/notes`) | Node 24, Hono, node:sqlite, sharp, Anthropic SDK |
| `tools` | Generators (icons, fonts, textures, widgets, emoji) and the dictionaries' check | Node, Python |

Below, `core/x`, `design/x` and `notes/x` are `packages/<name>/src/x`, imported as `@unlease/<name>/x` (a path alias in every program's tsconfig, bundler and test runner). The root is an npm workspace for `web/*` and `server` (one lockfile, installed at the root); each phone app is its own install (React Native pins its React, ESLint, Jest and Babel). One Docker image (root `Dockerfile`, `ghcr.io/stephenprn/unlease`) runs the server and serves the web apps on the same port. `docs/ARCHITECTURE.md` explains the suite (layout, data across apps, the server's apps), the sync, Carnet's link reading and the deviations from the house structure; `docs/SELF-HOSTING.md` how others run it; `docs/RELEASING.md` how a release is cut.

## Open source and deployment

- **Nothing specific to one infrastructure goes in this repository**: no real hostnames, IPs, bucket names, tokens, device serials or personal paths, in code, docs, tests or examples (use `example.org`, `192.168.1.20`, placeholders). The maintainer's own deployment lives in a separate infrastructure repository (an Ansible role pulling the published image); anything about it belongs there, or in the git-ignored `CLAUDE.local.md`.
- **Configuration is the environment or the apps**: start-up settings are `UNLEASE_*` variables (`server/src/config.ts`, documented in `docs/SELF-HOSTING.md`, `server/README.md` and `.env.example`); everything else (Claude, S3, Seafile, Seerr) is set from the apps' Administration. A new start-up setting goes in all four places; a new deployment shape (proxy, host) is a section of `docs/SELF-HOSTING.md`, never a code path for one host.
- **The image serves both**: `UNLEASE_WEB_DIR` points the server at the web build (`server/src/http/web.ts`: the app's page for any path outside `/api`, `_headers`'s security headers, hashed assets cached for good). The web app finds a server serving it (`servedByServer`) and fills in its address; hosted apart it needs `UNLEASE_CORS_ORIGINS`. The service worker never touches `/api`. A second web app will take a path of its own (`/notes/`, `/calendar/`), decided when it comes.
- **CI and releases** (`.github/workflows/`): `ci.yml` runs the packages' and each program's `verify` and the dictionary check on every push and pull request; `image.yml` publishes `:edge` (amd64 and arm64) from `main`. Keep them green. One version for the whole repository, set only by `npm run bump -- X.Y.Z` (`tools/release/version.mjs`: the four `package.json`, both lockfiles, Carnet's `versionName` and the `versionCode` computed from it); a `vX.Y.Z` tag (`vX.Y.Z-rc.N` a candidate) runs `release.yml`: the tag checked against them and the changelog, `ci.yml`, the image (`:x.y.z`, `:x.y`, `:latest`) and the APK (`android.yml`, signed with the upload key from repository secrets when they are set), then the GitHub release from `CHANGELOG.md` with a pinned `docker-compose.yml`, `example.env` and `SHA256SUMS`, then the web demo on GitHub Pages (`pages.yml`, `npm run build:demo -w web/notes`: the dev demo built as a static site under `/unlease/`; the router keeps app paths and adds Vite's `base` only to the browser's address, `browserPath`/`appPath` in `web/notes/src/ui/router.tsx`, so an `href` to an app path goes through `browserPath`) (`docs/RELEASING.md`).
- **Docs are for strangers**: `README.md` (what it is, install from the latest release, upgrade), `docs/` (mapped in `docs/README.md`), `CONTRIBUTING.md`, `SECURITY.md`, `SUPPORT.md`. Anything a person running Unlease would notice adds its line to `CHANGELOG.md` under Unreleased (Added, Changed, Deprecated, Removed, Fixed, Security; a break starts with **Breaking:** and says what to do); a new variable, a migration order or a break also goes in the docs it touches.

## Commands

```bash
npm install                          # the root workspace: the packages' tools, web/notes and server
npm run verify                       # shared packages: typecheck + lint + vitest
npm run verify -w web/notes          # Carnet on the web: typecheck + lint + vitest + build
npm run verify -w server             # server: typecheck + vitest
npm run dev -w web/notes             # web on http://localhost:5173; /?demo runs it on a fake server in the page (no key, nothing spent)
npm run dev -w server                # server from server/.env (UNLEASE_TOKEN, UNLEASE_DATA_DIR, UNLEASE_CORS_ORIGINS, UNLEASE_WEB_DIR)
(cd mobile/notes && npm install)     # Carnet for Android: its own install
(cd mobile/notes && LANG=fr_FR.UTF-8 npm run verify)  # typecheck + lint --quiet + jest (its screen tests read French)
(cd mobile/notes && npm run android) # on a device/emulator (Metro: npm start)
node tools/i18n/check.mjs            # every translated sentence has its English where its code can count on it (--unwrapped <path>: French left outside t())
docker build -t unlease .           # the image: server + web apps
docker compose up -d                 # the published image, from docker-compose.yml and .env
```

Java 17 for Gradle (`JAVA_HOME` pointing at a JDK 17). Generators run from the repository root.

## The suite

- **Dependencies point down:** `core <- design <- notes <- the programs`, enforced by the root ESLint for `packages/`: core and design know no app. The shared packages import no third-party module, platform or framework (no React, React Native, zustand, SQLite driver, Node or DOM API): they compile into Hermes, the browser and Node, and each program owns its dependencies.
- **Every app of the suite is in `core/apps.ts`** (`APPS`: id, name, slug), installed or not, so a reference into an app this server does not run still reads as the suite's. The names are written out there only (`SUITE_NAME`; Carnet's `APP_NAME` in `notes/brand` comes from `APPS.notes`): the literals are a lint error elsewhere. "Carnet" is also an ordinary French word: where content means a notebook, not the app, disable the rule on that line with the reason.
- **Record types are declared by their app** (`defineRecordTypes` in `core/sync/schema.ts`; Carnet's in `notes/sync/types.ts`): each field's check, the merged text fields with their limits and merge, the defaults a rollback writes back, the seeded ids. A type name belongs to one app for the whole suite (a second app declaring it throws). A program knows the types of the app packages it loads (`notes/sync/entities` loads Carnet's); a record of a type no loaded app declares is refused whole.
- **Ids are UUIDv7** (`createId`, `core/services/ids.ts`, RFC 9562), minted on the device, unique across apps and sorted by creation. Only records every device seeds keep a fixed id (`inbox`, the starter collections' `line-*`), so two devices make the same one.
- **A reference is a type and an id** (`core/refs.ts`: `REF_TYPES`, each type's app and record type): a mention `{@type=id}` in rich text, a block's `targetType`/`targetId`. Something new people can point at (another app's event, contact) gets a type there. A type this build does not know (a newer client's) is kept as it is, never dropped or rewritten, and shows as unavailable (« Indisponible ici »): every switch on a target's type has a `default`.
- **An app's part of the server is a `ServerApp`** (`server/src/apps/types.ts`; Carnet's in `server/src/apps/notes/`): its routes, background work, hourly chores, the files its records use, their layout under its own folder in Seafile and archives, its Markdown in archives, its push rules. The platform (`server/src/` outside `apps/`) never imports an app's package. A new app's module is listed in `server/src/main.ts` and `server/test/helpers.ts`.
- **Each package brings its English:** core's in `core/i18n/en/`, the design system's in `design/i18n/en.ts`, Carnet's in `notes/i18n/en/`; each program adds those it shows at start (`addNotesEnglish()` in Carnet's entry points and test setups). The check refuses a sentence whose English sits in a package its code cannot count on.

## Conventions that bite

- **Layers (phone):** `ui -> app -> data/platform -> packages`, enforced by `mobile/notes`'s ESLint. `ui` never imports `@data`.
- **Every user action is one `writeLocal` batch** (`mobile/notes/src/app/store/actions.ts`): one HLC tick, persisted as pending, synced. Undo writes the old values with a newer clock. Never mutate records another way.
- **Records are field-wise last-writer-wins** (`core/sync/record.ts`). Adding a synced field: add it to its type's declaration (`notes/sync/types.ts`) and `notes/sync/entities.ts`; never rename or remove one; ship the server before the apps (an older server drops the field for good).
- **Typed text merges instead** (a type's `merged` fields, `core/sync/textMerge.ts`; bases in `core/sync/bases.ts`): an editor saves what is typed through `saveTypedText(type, id, field, since, typed)` (not `updateNote`/`updateCheck`/`updateLink`), with `since` the text it last saved or showed. A new long free-text field goes in its type's `merged`, with its limit in `TEXT_LIMITS`.
- **A drawing is strokes as text** (`notes/services/drawing.ts`, a note of kind `drawing` in `note.drawing`, a page's `drawing` block in `block.drawing`): the field merges stroke by stroke (`mergeStrokes` through `mergeField`), so save it whole through `saveTypedText` (a note) or `saveBlockText(…, 'drawing')` (a block, kept in the page's undo), never another way. Coordinates are units of a sheet `DRAWING_WIDTH` wide; inks are keys (`ink` or a pigment), painted from the theme.
- **A text note's body is plain or formatted** (`note.rich`, `notes/services/noteBody.ts`: lines, `# `/`## `/`### ` headings, page rich-text marks): outside the editors read it through `bodyText(note)` (words) or `bodyMarkdown`, never `note.body`; the editors save through `saveNoteLines`. A plain note stays plain until its first mark.
- **Paper never moves the words:** the note editor's geometry is the same on every paper (a text note's title always keeps the ruled papers' skipped line; every body line, headings included, keeps the 26 pitch); ruled papers align on it, never the other way.
- **Positions from synced records go through `placeAt`** (or `positionBetween`/`positionsBetween` at an open end), never `keyBetween`: two devices can mint the same key, `keyBetween` throws between equal neighbours, and only `placeAt` fits an item between twins (it moves the later one; write its `moved` in the same batch).
- **A note's `color` is a pigment or a gradient** (`NoteColor`, `design/colors.ts`) and its paper is a separate `pattern`; collections and labels take pigments only (`asLineColor`). Both keys pass sync if well-formed: an unknown one draws plain. Paint a note with `noteBackdrop` (`design/backgrounds.ts`), the same CSS layers on both clients.
- **"Non classé" has the fixed id `inbox`** and is seeded with the genesis clock on every device. Never use its position as a neighbour for `placeAt` or `positionBetween`.
- **No underline or line-through on text cut by `numberOfLines` (phone):** React Native 0.88 draws decorations by hand and crashes when one falls past the last laid-out line (search "G" did). A card's search match is the peach background alone.
- **Never import `Text`, `Touchable*` or `Switch` from react-native:** `AppText`, `Tappable` and `Switch` from `@ui/components` (the web's switch, drawn the same: Android's own is off the system; a row that is the switch itself draws `SwitchMark`). `Tappable` draws its press tint inside the control's own corners (no `android_ripple`): give the control its shape in `style`. Set `fontFamily`, never `fontWeight` (each Signika weight is its own family; the night theme uses the `SignikaNight-*` grade).
- **A shaped surface on the phone is an `Organic`** (`@ui/components`, Android's `OrganicView`), or a `Tappable`, which paints itself with one: every corner is the continuous corner (`squircleSegments` in `design/shapes.ts`, mirrored number for number in `Squircle.kt`: keep the two in step). A plain `View` with `corners()` draws plain circles. Its border is one colour (a side may go without). Corners come from `SHAPES` by role (the `RADII` scale), never a radius per item or by size; a shape nested in another is concentric (`concentric`). A `Tappable` cannot clip: what must stay inside its shape sits in an `Organic` with `overflow: 'hidden'`.
- **The brand's pebble is the one organic form** (`design/pebbles.ts`, the mark's stone): state and identity only (an icon button's tint, the capture button, the chosen place, a collection's emblem on its stone `EmblemStone`, pictures, swatches, the tick), never text. Phone: `pebble={turn}` on an `Organic`/`Tappable` (it gives under the press, natively). Web: `data-pebble={turn}` clips the element, `data-pebble-under={turn}` paints its `::before` (`--pebble-fill`) so its focus ring stays whole; a ring is a `PebbleEdge` (mark the owner `data-still`). A collection's stone turns `pebbleTurnOf(id)`.
- **A container takes its kind's outline** (`design/outline.ts`: the continuous corner at the kind's radius, the same for every item and every size, capped at `CORNER_CAP` of the shorter side so a one-line note stays a sheet): on the phone `outline="card"` on an `Organic`/`Tappable`; on the web `useOutline('card')` (clip + `OutlineEdge`, the lift on an unclipped parent as `--drop-*`, a focus ring outside), `OutlinedBox`, or `data-outline="kind"` (+ `data-edge`) for plain blocks. Web controls take `border-radius: var(--cut-<role>)`, scaled by `--corner-scale` where the browser draws `corner-shape: squircle`. A clipped web element loses its own box-shadow and focus outline: lift and ring it from outside.
- **Colours come from `design/palette.ts`** through the theme (`useThemedStyles`). Its contrast test is the authority. A screen lies on the ground (`GROUNDS`, two tones of the wall): `Ground` on the phone, `var(--ground-paint)` on the web (its film grain over the two tones, both fixed), never the flat wall alone.
- **The primary, the accent and the ground are the device's appearance** (`design/appearance.ts`; Réglages > Couleurs and Fond, the first run's « Apparence »): read them resolved for the theme (`theme.color`, `theme.ground` on the phone; the custom properties `applyAppearance` lays on `<html>` on the web), never `ROLES`/`GROUNDS` for those roles; a pinned bar paints the ground's slice (`GroundSlice`). A colour a person picks is fitted to keep every ratio (`fitGround`, `primaryRoles`, `accentRoles`); a new preset passes `__tests__/appearance`. The mark's pebble follows the primary too: draw it with `markColors(primary)`, never `MARK_COLORS` alone (the launcher, widgets and install icons are static and keep matcha). Pictures handed to another service (Seafile's logo, favicon and login background, `design/servicePictures.ts`) are drawn and encoded in the design package (`raster.ts`, `png.ts`, `jpeg.ts`, no library), so both apps make the same bytes; each app only saves them. The web's security policy refuses inline stylesheets: colours set at runtime go through the CSSOM. The sheets' grain is the `grain` setting, the ground's is the appearance's.
- **Claude's key is a server setting set from the apps** (`GET/PUT /api/settings`, `core/sync/settings.ts`). Without it, links are kept plain (`status: 'skipped'`). Never put a key in source.
- **Claude writes in the link's language:** a link's `lang` is the interface language of the device that saved it (`getLocale()` in `addLinks`), set again when it is read again (`reanalyzeLink`, `readSkippedLinks`); the server names it on the message's first line (the system prompt stays fixed, so it stays cached) and reuses a cached reading only in the same language. Labels Claude writes come in both languages (`FACT_LABELS`, the prompt's lists); words the server matches against collection titles are French and English (`KIND_WORDS`).
- **Generated files:** `design/glyphs.ts` (`tools/icons/build_glyphs.mjs`, from Onde, Carnet's own icons drawn in `tools/icons/onde.mjs`: a new icon is drawn there, never imported), Android vector icons (`tools/icons/build_android_drawables.mjs`), the widgets' `wgen_*` resources and `WidgetRes.kt` (`tools/widgets/build_widget_resources.mjs`), the paper grain `mobile/notes/assets/textures/grain.png` and `web/notes/public/grain.png` and the ground's film grain `web/notes/public/ground-grain.png` and `mobile/notes/assets/textures/ground-grain.png` (`tools/textures/build_grain.py`), the emoji pickers' catalogue `design/emojiCatalogue.json`, shared by both apps, its search in `design/emojiSearch.ts` (`tools/emoji/build_emoji.mjs`, from the web's `emojibase-data`), fonts (`tools/fonts/build_fonts.py`), Signika's advance widths `design/advances.ts` (`tools/fonts/build_advances.py`). Collection emblems are data in `design/emblems.ts`, drafted by `tools/emblems/draft_emblems.py`; the mark's paths in `design/mark.ts`, by `tools/icons/draft_mark.mjs`.
- **Motion comes from `mobile/notes/src/ui/theme/motion.ts`** (web: `--ease-*`, `--duration-*`). An overlay plays its exit: keep its host mounted and render the animated child conditionally (Dialog, Menu, Snackbar), or drive it by hand (Sheet, Drawer); a subtree replaced whole skips its children's exits (`LayoutAnimationConfig skipExiting`, see `Wall`), or Reanimated misorders what draws over it.
- **Board cards are sized in the packages, never measured** (`layoutCard` in `notes/services/wall.ts`, Signika's widths): a card's paddings, rows and line counts must match it on both clients; change the anatomy there first.
- **A link's `filedBy` records who chose its collection** (`claude`, `person`, or null for "landed in Non classé"): an action that places a link on the person's say writes `person` (`moveLink`, `applyReview`, `trashLines` into another collection); "Ranger Non classé" (`inboxToSort`) skips those. Claude's later sorting goes through `POST /api/sort` and `applyMoves`, never the analyzer.
- **A link module** goes in `LINK_MODULES` with its name, description, fits, icon, needs and group (`notes/models/modules.ts`), its test in `moduleFits` (`notes/services/modules.ts`), and both clients' `ModuleBar` (its dialog or sheet); the "Modules" sheets list it on their own. One that asks the server gets a route in `server/src/apps/notes/routes.ts`, its stand-in in `web/notes/src/dev/fakeServer.ts`, its own `ModuleTask` in `analyses`, and, when it searches the web, goes through `LinkSearches` (a variant of the same link, as a recap's episode, is kept under its own mark). Modules write nothing to the link on their own (an answer goes in its note only when the person adds it). Recipe scaling and step timers are core (`notes/services/recipes.ts`); the servings and timers are each app's memory (`kitchen.ts`).
- **A link is added through `addLinks`** (both apps' actions): it keeps an address once per collection and copies a reading from another collection (`notes/services/savedLinks.ts`); show its `addedMessage`. A new way to add links goes through it, never `writeLocal`.
- **Deleting collections that hold links asks where the links go** (`collectionsWithLinks`; phone `DeleteLineSheet`, web `askDeleteLines`): a new way to delete notes goes through it, never `trashNotes` alone. "Non classé" is never deleted nor asked about.
- **The web app has two spaces, notes and pages** (`web/notes/src/ui/navigation/space.ts`): a new route goes in `spaceOf` (or stays shared, as the bin and the settings), so the navigation shows the right one.
- **Home-screen widgets draw what JavaScript hands them** (`mobile/notes/src/app/widgetPayloads.ts`, sent by `mobile/notes/src/app/widgets.ts`): what a widget shows changes there, never by reading SQLite in Kotlin; a write from a widget goes back through JavaScript (a tick: `setChecks`). Their resources come from `tools/widgets/build_widget_resources.mjs` (`wgen_*`, `WidgetRes.kt`); a widget layout takes no `View`/`Space` (a launcher refuses them) and no app font (titles: `WidgetType.kt`).
- **The web demo answers the server's routes itself** (`web/notes/src/dev/fakeServer.ts`, `/?demo`): a new route needs its stand-in there.
- **URL lists are "collections" in the UI** ("lines" in the code: `Line*`, `useLines`, `createLine`); labels are "labels". A collection wears a cut-out emblem (`note.emblem`), "Non classé" the inbox tray (`'bac'`).
- **Inline atoms in rich text** (a mention `{@type=ID}`, a date `{@date=…}`) count one character in every offset: a new kind goes in `core/services/richText.ts` (parse, serialize, `richToPlain`, `sliceRich`), `richDisplay.ts` (the phone's fields), the web's `richDom.ts`, `pageText.ts` (Markdown) and every `run.kind` switch (TypeScript lists them).
- **Pages are `block` records (web and phone):** a page is a block and `parentId` its container (`notes/models/blocks.ts`). Change them through the page actions (`web/notes/src/app/store/pages.ts`, mirrored by the phone's `mobile/notes/src/app/store/pages.ts` and `pageHistory.ts`: one batch each, recorded in the page's undo history; change both together), never with `writeLocal` directly. Rich text is markup (`core/services/richText.ts`): edit it as runs (`parseRich`, `serializeRich`), never by slicing the string; a mention counts one character.
- **A new block kind** goes in `BLOCK_KINDS` and the schema, both clients' `BlockView`, the `/` menu (web `slashCommands.ts`, phone `PageSheets.tsx` `COMMANDS`), the clipboard (`clipboard.ts` `KEPT`, `notes/services/pageText.ts`), what Claude reads of a page (`blockWords` in `notes/services/pagesAsk.ts`), the backups' Markdown (`server/src/apps/notes/markdown.ts`), and if it holds a file the files in use and their layout (`notesFilesInUse`, `layoutLibrary` in `server/src/apps/notes/files.ts`: the collector, the drive and the archives).
- **Questions about pages are built on the device** (`askContext`, `notes/services/pagesAsk.ts`): never send a page whose `isPrivatePage` holds (its own `private` or a page above it), nor one in the bin; what goes to Claude is fixed English labels around the person's own words.
- **Server settings live in the Administration** (web `/admin`, phone `Admin`), not in Réglages (the device's own). A new one goes in `core/sync/settings.ts` (view and patch), `server/src/settings/store.ts` and `update.ts` (checked, and tried when it connects to something, before anything is stored), both Administration screens and the web demo; the first run's setup (`core/services/setup.ts`, both `SetupScreen`s) shows those same sections, as the rows of « Votre serveur » (only on a server that held nothing when the device came; a device joining one in use goes straight to the board). Secrets never leave the server: only their last four characters.
- **A blob's original may live in the drive** (Seafile): read blob bytes through `BlobStore.open` (`read()`), never from `blobs/` paths directly.
- **Every sentence the interface shows goes through `t()`** (`core/i18n`): the French is the key, its English goes in the area's part of its package's dictionary (Carnet's screens: `notes/i18n/en/`; `node tools/i18n/check.mjs` lists what is missing; `--unwrapped <path>` finds French left outside). One sentence per key with `{slots}`, never fragments; `tc(context, …)` where one French needs two English (« Annuler »: `tc('undo', …)` on a slip); never `t` at module scope (a constant is `tx('…')`, translated where shown; a names map is `localized({…})`). Dates, numbers and `plural` follow the language already. A title shown goes through `shownTitle(note)` (the seeded « Non classé »). Nothing stored, synced or sent to Claude is translated.
- **A slip says its tone:** `showSnack(message, action, { tone })` with `info` (default), `success`, `warning` or `error` (web helpers `showError`, `showWarning`, `showUndo`).
- **Git:** never commit or push unless asked.
